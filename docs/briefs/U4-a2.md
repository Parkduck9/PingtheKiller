## Fix list
1. **MoveInput rate (blocker; cross-unit contract ruled by the orchestrator, overrides U4-a1 §7 "every frame").** The server drops any MoveInput beyond 60 per second, so per-frame sending at 144 fps loses the release-zero and the survivor keeps walking. New rule:
   - While any movement key is held, send at a fixed **30 Hz** using an accumulator on unscaled time, independent of frame rate (at most one send per frame; do not burst to catch up after a hitch — drop missed slots).
   - On release, send a zero-direction MoveInput **immediately in that frame**, and **once more** at the next 30 Hz slot as a backup; then nothing while idle.
   - Total ≤ 31 sends in any sliding 1 s window (steady hold = 30 ± 1/s).
   - Seq strictly increases across every send. Keep one Seq counter per connection (create it with the `NetClient`, not per `S2C_MatchStart`) — QA-07.
   - Put all of this in the pure class `MovementInput` with an explicit `dt`/time parameter so it is EditMode-testable; `ClientApp` only reads keys and calls it.
   - Note: the server (U2a a2) moves a survivor only while its input is fresh (≤ 0.15 s), so the 30 Hz stream must continue the whole time a key is held.
   - Tests: simulated 144 fps and 30 fps for 1 s of hold → 30 ± 1 sends; a 250 ms frame hitch does not produce a burst; release produces a zero send in the same frame and one backup zero at the next slot, then silence; Seq monotonic across hold → release → hold.
2. **USS selectors (QA-01, V10 gate risk).** Type selectors (`Button`, `Label`) lose to the default theme's class selectors (`.unity-button`, `.unity-label`, `.unity-text-field__input`). Rewrite `ClientUI.uss` to use class selectors with at least the theme's specificity (e.g. `.root .unity-button`, `.root .unity-button:hover`, `:active`, `:focus`, `:disabled`, `.root .unity-label`, `.root .unity-text-field__input`) so the flat palette, 1 px line, 2 px radius and all five states actually apply. Keep the palette and no-gradient/no-shadow rules.
3. **Spacing scale (QA-03, SLOP L6).** Every margin/padding/gap must be from 4/8/12/16/24/32. (Control heights/widths such as a 48 px button height are sizes, not spacing, and may stay.) Replace `margin-left: 64px; margin-top: 48px` etc.
4. **Killer Esc (QA-02).** The killer's cursor is never locked; Esc must not stop the killer's movement, and the killer HUD must not show the cursor hint. The survivor hint stays (`Esc: release cursor` / `Click to resume mouse look`).
5. **Beep clip seam (QA-04).** Extract a pure `public static float[] BuildBeepSamples(int sampleRate)` (880 Hz, 60 ms, short envelope) used by `ThreatAudio`; make `SetLevel` safe before `Awake`. Test: sample count = round(rate × 0.06), zero-crossing count consistent with 880 Hz (≈ 2 × 880 × 0.06 ± 2).
6. **Beep timing on level change (QA-13).** Rising threat → beep now and restart the schedule; falling threat → do not beep immediately; next beep at `min(scheduledNext, lastBeep + newInterval)`. Pure, testable helper; add a test.
7. **RTT (QA-08).** Compute RTT from the packet's arrival timestamp (`Received.Time` taken on the receive thread), not from `Pump` time.
8. **Hot-path allocations.** `NetClient` receive loop: remove `packet.Id.ToString().StartsWith("C2S_")` (string alloc per packet) — use a numeric/type check. `WorldView.Accept`: reuse the terminal `HashSet`/`List` fields instead of allocating per WorldState.
9. **BuildScript side effects.** Remove `[InitializeOnLoad]`/`delayCall` asset creation on every editor load; `EnsureAssets` runs only from `BuildWindows` (and an optional `MenuItem`). The committed scene/materials already exist.
